# NoTouch 0.6 — 거리·머리 보정 실험

## 사용 순서
1. 카메라를 시작한다. 상태에 거리 추정(cm)이 나타나는지 확인한다. 접근성은 눈 조작에만 필요하며 수집·학습에는 필요 없다.
2. 참가자 코드를 입력하고 `목표 60개 보고 터치하여 데이터 수집`을 실행한다. 목표의 흰 중심을 1초 이상 바라본 뒤 파란 원을 누른다. 목표 좌표가 학습 정답이며 터치 좌표는 확인용 기록이다.
3. 자로 확인한 30cm, 45cm 등 서로 다른 거리에서 각각 세션을 완료한다. 세 번째 세션은 별도 평가용으로 다시 촬영한다. 목표 사이에는 작은 머리 회전을 포함하고, 한 목표를 수집하는 동안에는 자세를 유지한다. 거리 입력 모델은 학습 데이터에 최소 8cm의 추정 거리 범위를 요구한다.
4. `수집 데이터로 학습 · 거리 포함/제외 평가`를 누른다. 완료된 세션 중 마지막 세션만 평가에 사용하고 나머지로 두 모델을 학습한다. 평가 세션으로 재학습하지 않는다.
5. 거리 포함 모델이 자동 적용·저장된다. 재시작해도 같은 기기·화면 방향에서 불러온다. 작은 표본으로 정확도 향상을 보장하지 않으므로 평가 수치를 비교한다. 9점 보정 또는 기존 JSON 모델을 선택하면 새 모델 대신 해당 선택을 사용한다.
6. 수집 CSV와 평가 JSON을 시스템 파일 선택기로 내보낼 수 있다. 수집 데이터는 얼굴 사진 없이 숫자 특징만 앱 내부에 저장한다.

## 구현
- 기존 MediaPipe Face Landmarker 사전학습 모델 유지, canonical-face 변환 행렬에서 yaw/pitch 추출. 절대 거리로 landmark z를 사용하지 않는다.
- Camera2의 고정 초점거리, 물리 센서 크기, active-array 비율, 스트림 종횡비의 중앙 크롭을 사용해 픽셀 초점거리를 근사한다. 줌은 1배. 평균 홍채 직경 11.7mm를 가정한다. 광학 왜곡·제조사 추가 크롭·개인 홍채 크기는 잔여 오차 원인이다. 반드시 자로 실기기 검증할 것.
- 양 눈 거리 추정이 25% 이상 다르거나 15–100cm 밖, 홍채 직경 4픽셀 미만, 머리 yaw/pitch 절댓값 약26도 이상이면 거리 불명 처리. 원근에 따른 홍채 축소를 정확히 역보정했다는 주장은 하지 않는다.
- 특징: 기존 10개 + 거리/40cm + head yaw/pitch(rad). 거리 포함 ridge 회귀에 눈 특징×거리 상호작용 추가. 비교 모델은 같은 데이터의 명시적 거리 및 상호작용만 제외한다. 얼굴 크기는 양 모델에 남아 있으므로 거리 정보를 완전히 제거한 비교는 아니다.
- 학습 표본은 터치 50–450ms 전의 유효 프레임 최소5개 중앙값. 눈·머리·거리 변화가 큰 표본은 거절한다. 터치와 시선의 일치를 보장하는 전문 장비 정답은 아니다.
- 조작에는 시간 간격을 반영한 적응형 평활화를 적용한다. 큰 이동은 빠르게, 작은 변화는 강하게 완화한다. 깜빡임 클릭은 기존 상태 머신의 눈 감기 직전 좌표를 유지한다.
- 새 모델 실행 중 GPT 좌표가 로컬 모델을 대체하지 않는다. 기존 GPT 후보 추천 실험은 별도이다. LLM 강화학습은 이 버전의 학습 방법이 아니다.

## 평가와 한계
평가 JSON의 all_predictions에는 거절될 범위의 예측도 포함하여 실패를 숨기지 않는다. accepted_predictions 및 coverage를 별도 기록한다. 오차 단위는 x/화면너비, y/화면높이 좌표의 유클리드 거리이며 cm·시야각이 아니다. 현재 평가는 목표별 중앙 특징을 사용하므로 프레임별 흔들림·지연 측정은 포함하지 않는다. 참가자별 일반화는 별도의 참가자 holdout 실험이 필요하다.

개발 데이터가 아직 수집되지 않았으므로 이 버전에 미리 학습된 거리 보정 가중치는 없다. MediaPipe는 사전학습 상태이고, 시선 보정 가중치는 위 수집·학습에서 생성된다. 학습 전 기본 포인터는 경험적 근사로 표시한다. 앱 빌드·계산 테스트는 실제 눈의 정확도 검증을 대신하지 않는다.

## 파일
- 앱 내부: files/datasets-v3/session-<UUID>.csv, files/depth-model.json, files/depth-evaluation.json
- 기존 v2 CSV는 별도 보존하며 혼합하지 않는다. training/train.py는 기존 v2용이고 v3은 앱 내부 학습을 사용한다.
- 미완성이던 MobileOne ONNX 코드는 호출하지 않는다. 기존 소스를 유지하기 위해 런타임 의존성을 복구했으며, 새 학습 경로는 해당 모델에 의존하지 않는다.
